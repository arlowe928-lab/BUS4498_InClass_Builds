# Stage 11: install the club list

Deployment update (November 2, 2026): during the later authorized Stage 14 deployment, this SQL was applied as a prerequisite and the club-aware `submit-event` was deployed with JWT verification off; its GET status reports six active clubs. No test posts were sent. The manual instructions below are retained for reference. Keep your existing GroupMe source/duplicate protection and photo support. The website already includes the Stage 11 notes display and Tools tab, so no website rewrite was needed.

1. Open your [Supabase project](https://supabase.com/dashboard/project/sybducqavyxvbqnimrbk) → **SQL Editor → New query**. Copy the entire contents of `supabase/migrations/20261030001100_club_list.sql` from this folder, paste into the query, and click **Run**. This creates the six starter clubs, adds `agent_notes` to `events`, and lets signed-in moderators use Clear the board. Existing posts and existing club edits are preserved if you run it again.
2. Open **Edge Functions → submit-event → Code**. Copy the entire contents of `supabase/functions/submit-event/index.ts` from this folder and replace the complete contents of the function's `index.ts`. Click **Deploy** (or **Deploy updates**). Under **Details**, keep **Verify JWT off**. No new secrets are required. Uploading with GitHub Desktop does not deploy the function or run the SQL.
3. In **Authentication → Sign In / Providers**, confirm **Allow new users to sign up** is off: this project treats every provisioned signed-in account as a moderator, including permission to clear posts. Create moderator accounts through **Authentication → Users → Add user** as needed.
4. In **Table Editor → clubs**, expect six starter rows, with RLS enabled. The agent reads active rows before every new decision; edit names, comma-separated nicknames, usual places, or active switches here. The public website can read only active club IDs, names, nicknames, and active flags; usual places and notes stay private to the backend.
5. Run the builder's **Check the club list**. Expect the agent to report six active clubs (or your updated count). Its [GET status](https://sybducqavyxvbqnimrbk.supabase.co/functions/v1/submit-event) now includes `clubs`; GET reads the database but does not call the AI or validate the AI key.
6. When ready, use posts A–D in `test/week10-announcements.md` while their dates are still upcoming (otherwise update the dates). A should publish as **Board Game Guild**, B should wait for an unlisted club, and C should publish after you add **Cal Poly Kite Flyers** with nicknames **kite flyers, kite club** in Table Editor. D should wait for a missing place while showing **University Union (UU), Room 220** as a hint. In both the posting result and moderator queue, expect **What the agent looked at**. Clear the board is available in the moderator Tools tab and requires confirmation; only use it when you intend to delete the posts.

The agent now loads the active `clubs` table before calling the AI, matches the longest club name or nickname in the announcement, and puts official names and nicknames in its prompt. Code writes the official name and holds unknown or missing clubs for review. A usual meeting place is a hint only and is never sent to the AI or copied into an event's missing location. Each saved decision records what was checked in `events.agent_notes` and returns it as `looked_at`. Earlier-event memory and lessons are later stages.

The earlier live log showed OpenAI HTTP 401. If that is still unresolved, replace `OPENAI_API_KEY` in Supabase → Edge Functions → Secrets with a valid key; a successful GET status only confirms that a value exists, not that OpenAI accepts it. Never paste a secret into chat or repository files.

Offline checks, from the repository root: `node event_radar/test/stage11-offline.mjs` and `node event_radar/test/stage14-offline.mjs`. These mock the database and AI and send no real posts. SQL permissions must still be checked in your dashboard after you apply the migration.

References: [Supabase row-level security](https://supabase.com/docs/guides/database/postgres/row-level-security), [dashboard function deployment](https://supabase.com/docs/guides/functions/quickstart-dashboard).
